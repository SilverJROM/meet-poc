# codex55 verdict — T1 round 4
## Q1 — Architecture: Option A confirmed? (or named alternative + why) — evidence file:line
**Option A is confirmed as the right architecture**, but only if implemented as a service-owned per-element playout registry, not just by flipping `[remoteAudioEnabled]`.

Reason: Option A structurally removes both agreed root mechanisms. A3 cannot happen because the audible path no longer uses `AudioContext`, `gain`, `limiter`, or `MediaStreamAudioDestinationNode` (current graph is at frontend/src/app/services/remote-audio.service.ts:171, frontend/src/app/services/remote-audio.service.ts:172, frontend/src/app/services/remote-audio.service.ts:174, frontend/src/app/services/remote-audio.service.ts:507). A4 is reduced because each tile uses a direct `HTMLAudioElement.srcObject = peer.stream` instead of the single Web-Audio destination stream (frontend/src/app/components/tile/tile.component.ts:57, frontend/src/app/components/tile/tile.component.ts:60; current mixer binds destination stream at frontend/src/app/services/remote-audio.service.ts:528, frontend/src/app/services/remote-audio.service.ts:541).

Option B is not safer for JROM's actual failure because it still ends in `MediaStreamAudioDestinationNode.stream -> <audio> -> setSinkId`, the same fragile class as A4. It preserves gain/limiter, but preserving the suspected broken transport is the wrong trade. The code has no other functional dependency on the remote-audio AudioContext that cannot be replaced: room debug and banner effects consume `contextState`, `sourcesVersion`, `outputPlaying`, `hasSources`, and `debugSnapshot()` (frontend/src/app/pages/room/room.page.ts:595, frontend/src/app/pages/room/room.page.ts:650, frontend/src/app/pages/room/room.page.ts:663, frontend/src/app/pages/room/room.page.ts:665), but these are mixer-health signals, not required for direct playout. They must be replaced with per-element health signals.

## Q3 — End-to-end trace: first breaking step (or "no break found across all steps")
**First breaking step in the revised design as written: publisher A subscribes and the tile mounts.**

Trace:
- Host join gesture calls `unlockAudioFromGesture()` before any future remote tile may exist (frontend/src/app/pages/room/room.page.ts:853, frontend/src/app/pages/room/room.page.ts:2661).
- Host publishes and remote publisher A is subscribed through `doSubscribeTracks()`; ontrack adds publisher A's stream by publisher ID (frontend/src/app/services/sfu-client.service.ts:1609, frontend/src/app/services/sfu-client.service.ts:804, frontend/src/app/services/sfu-client.service.ts:820, frontend/src/app/services/sfu-client.service.ts:826).
- Room `peers()` exposes that stream to tile rendering (frontend/src/app/pages/room/room.page.ts:327, frontend/src/app/pages/room/room.page.ts:331).
- The tile audio effect currently sets `srcObject`, forces `muted=false`, and immediately calls `play()` (frontend/src/app/components/tile/tile.component.ts:57, frontend/src/app/components/tile/tile.component.ts:60, frontend/src/app/components/tile/tile.component.ts:61, frontend/src/app/components/tile/tile.component.ts:63).

That first remote-audio mount still breaks unless B1/B8/B9 are implemented through a central per-element registry: it does not apply selected sink before play, does not honor mute/volume, and depends on a later room peer effect to route the sink (frontend/src/app/pages/room/room.page.ts:685, frontend/src/app/pages/room/room.page.ts:690). If the element's initial non-gesture `play()` rejects, tile emits the banner (frontend/src/app/components/tile/tile.component.ts:65), but if the implementation does not also replace the mixer-coupled banner/recovery effects, recovery can still be suppressed by `hasSources()` false (frontend/src/app/pages/room/room.page.ts:657, frontend/src/app/pages/room/room.page.ts:2687). Therefore the first broken arrow is: **publisher A subscribes -> tile audio mounts -> selected sink/volume/mute/play are not atomically applied before play.**

With B1/B8/B9 implemented correctly, the rest of the real-call trace has no additional structural break found:
- Publisher B joins: normal subscribe/ontrack is additive by publisher ID (frontend/src/app/services/sfu-client.service.ts:820, frontend/src/app/services/sfu-client.service.ts:826), and per-peer tiles provide concurrent audio without active-speaker gating (frontend/src/app/components/tile/tile.component.html:14; frontend/src/app/services/active-speaker.service.ts:41).
- Host changes output: `changeAudioOutputDevice()` persists only after `applySpeakerDevice()` succeeds (frontend/src/app/pages/room/room.page.ts:1030, frontend/src/app/pages/room/room.page.ts:1033), and registered elements must receive the new sink.
- Volume/mute-all: works only after B1/B3 fixes.
- A starts screen-share: works only after B4 exactly-one-audio-element dedup; current layout duplicates presenter/strip (frontend/src/app/pages/room/room.page.html:249, frontend/src/app/pages/room/room.page.html:273).
- B leaves/rejoins: `removePeer()` tears down subscription state (frontend/src/app/services/sfu-client.service.ts:968, frontend/src/app/services/sfu-client.service.ts:990), and fresh presence/subscribe can recreate the element.
- Background/resume: visibility recovery calls `recoverRemoteAudio('visibility')` (frontend/src/app/pages/room/room.page.ts:2876, frontend/src/app/pages/room/room.page.ts:2879), which must run the new per-element `recoverPlayback()`.
- Second remote starts/stops talking: active-speaker remains UI-only and does not suppress audio (frontend/src/app/services/active-speaker.service.ts:126, frontend/src/app/services/active-speaker.service.ts:128).

## New issue (11th+) found  — or  "NO NEW ISSUE — revised design complete"

Required fix: lower `MAX_VOLUME` to 1, clamp stored values on `readStoredVolume()`, persist the downgraded value, and update tests/UI labels.
