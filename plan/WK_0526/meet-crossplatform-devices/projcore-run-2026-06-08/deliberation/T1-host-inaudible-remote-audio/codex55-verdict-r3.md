# codex55 verdict — T1 round 3 (red-team)
## Blockers found in the fix plan (each: what breaks + file:line + how to fix)
1. **BLOCKER: retiring the audible mixer drops speaker volume + mute-all unless per-element audio is wired to `RemoteAudioService`.** Today the controls mutate `remoteAudio.volume()` / `remoteAudio.mutedAll()` (frontend/src/app/components/controls-bar/controls-bar.component.ts:70, frontend/src/app/components/controls-bar/controls-bar.component.ts:108, frontend/src/app/components/controls-bar/controls-bar.component.ts:119), but those signals only affect the Web-Audio gain node (frontend/src/app/services/remote-audio.service.ts:195, frontend/src/app/services/remote-audio.service.ts:200, frontend/src/app/services/remote-audio.service.ts:204, frontend/src/app/services/remote-audio.service.ts:516). Tile audio directly sets `audio.muted = false` and never reads volume/mute-all (frontend/src/app/components/tile/tile.component.ts:57, frontend/src/app/components/tile/tile.component.ts:61). **Fix:** add a per-element sink registry in `RemoteAudioService` or pass volume/mutedAll into `TileComponent`; set `audio.volume = mutedAll ? 0 : min(volume, 1)` and `audio.muted = mutedAll`, with an explicit decision for >100% amp (cannot be done on native element alone).
2. **BLOCKER: feedback limiter is lost on direct per-tile audio.** The brick-wall limiter was specifically added to tame same-room feedback (frontend/src/app/services/remote-audio.service.ts:56, frontend/src/app/services/remote-audio.service.ts:58, frontend/src/app/services/remote-audio.service.ts:519, frontend/src/app/services/remote-audio.service.ts:527), and its test only asserts constants (frontend/src/app/services/feedback-limiter.spec.ts:4). Direct tile playback bypasses `gain -> limiter -> destination` (frontend/src/app/services/remote-audio.service.ts:530, frontend/src/app/services/remote-audio.service.ts:532). **Fix:** either accept removal only with an explicit same-room-feedback mitigation (AEC/source capture settings plus no 130% amplification), or keep a per-publisher Web-Audio chain whose output element is not a single shared SPOF. If the implementation chooses direct native audio, remove/replace the limiter contract and test it intentionally.
3. **BLOCKER: share layout can double-play the same remote publisher.** When a remote screen share is active, the sharing peer is rendered once in the share stage and again in `orderedStripPeers()` because that computed returns all peers (frontend/src/app/pages/room/room.page.ts:424, frontend/src/app/pages/room/room.page.ts:438, frontend/src/app/pages/room/room.page.ts:444). The template creates an `app-tile` for the presenter and another for every strip peer (frontend/src/app/pages/room/room.page.html:249, frontend/src/app/pages/room/room.page.html:272). Re-enabling tile audio everywhere would create two unmuted `<audio data-remote-audio>` elements for the same remote stream. **Fix:** in share layout, disable audio on duplicate visual tiles and leave exactly one audible element per remote peer, or remove the presenter from the strip while share-stage tile owns audio.
4. **BLOCKER: mid-overwrite guard must not be a permanent throw.** The no-renegotiation branch currently overwrites `midToEntry` blindly (frontend/src/app/services/sfu-client.service.ts:1747, frontend/src/app/services/sfu-client.service.ts:1751, frontend/src/app/services/sfu-client.service.ts:1753). A guard that simply throws on a legitimate CF mid reuse could leave the new publisher unsubscribed, violating the no-suppression directive (plan/WK_0526/meet-crossplatform-devices/projcore-run-2026-06-08/north-star.md:35). **Fix:** on cross-publisher mid collision, rollback the local mutation and drive a safe recovery: close/re-subscribe stale/ambiguous mids or force a renegotiating subscribe retry, with bounded retry diagnostics. Do not mark the publisher permanently subscribed/failed.

## Regressions the fix would introduce (volume/mute-all/feedback-limiter/sink/autoplay) + mitigation
- **Selected output routing mostly survives, but only if peer-add routing remains.** Tile audio elements are selected by `document.querySelectorAll('video, audio')` in `applySpeakerDevice()` (frontend/src/app/pages/room/room.page.ts:2647, frontend/src/app/pages/room/room.page.ts:2648), and the effect reruns on `this.peers()` changes when a non-default device is selected (frontend/src/app/pages/room/room.page.ts:685, frontend/src/app/pages/room/room.page.ts:687, frontend/src/app/pages/room/room.page.ts:690). Mitigation: keep that effect, and make the per-element registry apply the current selected sink immediately on element registration, not only after Angular's peer effect.
- **Default speaker path is intentionally not re-applied on peer add.** The peer effect returns when `!deviceId` (frontend/src/app/pages/room/room.page.ts:688), so default-selected new tiles use browser/system default. That is acceptable if default means no app routing, but diagnostics must record empty/default separately from a selected device.
- **Autoplay recovery is wired, but fragile if the mixer is retired without updating playability.** Tile `play()` rejection emits `remoteAudioBlocked` (frontend/src/app/components/tile/tile.component.ts:63, frontend/src/app/components/tile/tile.component.ts:65), room sets the banner (frontend/src/app/pages/room/room.page.ts:1045), and unlock loops all `audio[data-remote-audio]` elements (frontend/src/app/services/remote-audio.service.ts:282, frontend/src/app/services/remote-audio.service.ts:287). Mitigation: change playability/debug logic so per-element paused state is authoritative when the mixer is not the audible path; current mixer effect early-returns when mixer `hasSources` is false (frontend/src/app/pages/room/room.page.ts:654, frontend/src/app/pages/room/room.page.ts:657).
- **Mute-all currently also disables the remote voice watchdog.** Watchdog skips recovery when `remoteAudio.mutedAll()` is true (frontend/src/app/pages/room/room.page.ts:2733) and passes mutedAll into recovery decisions (frontend/src/app/pages/room/room.page.ts:2783, frontend/src/app/pages/room/room.page.ts:2786). That remains valid only if per-element mute-all actually mutes the elements.
- **130% amplification cannot be preserved with native element volume alone.** `MAX_VOLUME` is 1.3 (frontend/src/app/services/remote-audio.service.ts:49, frontend/src/app/components/controls-bar/controls-bar.component.html:162), but `HTMLMediaElement.volume` tops out at 1. Mitigation: cap the UI to 100% on direct audio, or keep a per-publisher Web-Audio gain path for amplification while avoiding a single shared output sink.

## Confirmations (fix points that survive red-team)
- **Per-tile audio is already concurrent and non-suppressing.** Each non-local tile conditionally renders its own audio element (frontend/src/app/components/tile/tile.component.html:14, frontend/src/app/components/tile/tile.component.html:15), and the tile code does not gate playback on active speaker (frontend/src/app/components/tile/tile.component.ts:57, frontend/src/app/components/tile/tile.component.ts:63). Active speaker is analyser/UI-only with a zero-gain sink (frontend/src/app/services/active-speaker.service.ts:41, frontend/src/app/services/active-speaker.service.ts:126, frontend/src/app/services/active-speaker.service.ts:128).
- **Current template is the reason tile audio is off.** Room binds `[remoteAudioEnabled]="!remoteAudioMixerEnabled()"` in the main tile paths (frontend/src/app/pages/room/room.page.html:253, frontend/src/app/pages/room/room.page.html:273, frontend/src/app/pages/room/room.page.html:293), while `remoteAudioMixerEnabled()` is always true (frontend/src/app/pages/room/room.page.ts:222). Removing/replacing that gate really does re-enable the existing path.
- **Sink fallback exists per media element.** `applyMediaElementSinkWithDefaultFallback()` retries `setSinkId('')` on selected sink failure and clears stored selected output through the callback (frontend/src/app/services/remote-audio.service.ts:94, frontend/src/app/services/remote-audio.service.ts:103, frontend/src/app/services/remote-audio.service.ts:106), and `changeAudioOutputDevice()` only persists the chosen output after `applySpeakerDevice()` succeeds (frontend/src/app/pages/room/room.page.ts:1030, frontend/src/app/pages/room/room.page.ts:1033, frontend/src/app/pages/room/room.page.ts:1035).
- **R2/no-suppression is preserved if duplicates are handled.** The peer list is one tile per peer in normal grid (frontend/src/app/pages/room/room.page.html:286, frontend/src/app/pages/room/room.page.html:287), and the app-level directive forbids talker limiting (plan/WK_0526/meet-crossplatform-devices/projcore-run-2026-06-08/north-star.md:35, plan/WK_0526/meet-crossplatform-devices/projcore-run-2026-06-08/north-star.md:36).
- **R3 diagnostics are directionally correct.** Current inbound stats only read `inbound-rtp` fields including `audioLevel` (frontend/src/app/services/sfu-client.service.ts:728, frontend/src/app/services/sfu-client.service.ts:749), so adding `media-playout` and per-element playout state would disambiguate decode-vs-output. Privacy risk is low if device IDs are hashed/redacted; raw selected device IDs are already present in diagnostics payload today (frontend/src/app/services/meeting-sessions.service.ts:356, frontend/src/app/pages/room/room.page.ts:3509).
