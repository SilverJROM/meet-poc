# codex55 CODE red-team CR5 (lens L5: adversarial inputs / browser quirks / error paths)

## Findings by probe (1-7)

1. **BUG - setSinkId-unsupported browsers misreport selected sink.** `canSetSinkId()` correctly detects unsupported browsers for the picker (`frontend/src/app/pages/room/room.page.ts:224`, `frontend/src/app/pages/room/room.page.ts:3911`), and playback still proceeds through the browser default because `applyMediaElementSinkWithDefaultFallback()` returns without calling `setSinkId` (`frontend/src/app/services/remote-audio.service.ts:133-135`) before `el.play()` (`frontend/src/app/services/remote-audio.service.ts:465-480`). But when a stale/non-empty `selectedAudioOutputId` exists, the helper returns `'selected'`, `updateSinkFallbackState()` records that stale id as `effectiveSinkId` (`frontend/src/app/services/remote-audio.service.ts:517-523`), and `selectedSpeakerUnavailable` remains false (`frontend/src/app/pages/room/room.page.ts:673-677`, `frontend/src/app/pages/room/room.page.ts:1017-1022`). Diagnostics can therefore say "selected" even though the browser cannot route to selected output and is necessarily using default.

2. **BUG - garbage RTCStats can produce false voice-stall verdicts.** Live collection sanitizes undefined/null/NaN/Infinity to null (`frontend/src/app/services/sfu-client.service.ts:745-754`, `frontend/src/app/services/sfu-client.service.ts:1876-1878`), and missing samples clear stalls (`frontend/src/app/pages/room/room.page.ts:2748-2753`). However negative finite counters/energy are accepted as usable (`frontend/src/app/pages/room/room.page.ts:3915-3920`, `frontend/src/app/services/remote-audio.service.ts:619-620`). A sequence like `bytesReceived: -1 -> 10`, flat `jitterBufferEmittedCount`, and `totalAudioEnergy: -2 -> -1` passes `remoteVoiceBytesClimbed()` and `sampleWindowHasVoiceEnergy()` (`frontend/src/app/pages/room/room.page.ts:3928-3930`, `frontend/src/app/services/remote-audio.service.ts:105-120`), so `decideVoiceRecovery()` can trigger recovery/banner from invalid stats (`frontend/src/app/services/remote-audio.service.ts:71-85`, `frontend/src/app/pages/room/room.page.ts:2775-2808`).

3. **OK - autoplay rejection variants are caught and surfaced as blocked.** `addPublisher()` catches any `play()` rejection, including `NotAllowedError`, `AbortError`, and `NotSupportedError`, then marks the entry blocked (`frontend/src/app/services/remote-audio.service.ts:479-493`). Gesture unlock and recovery replay through `unlockAndPlayRemoteSinks()` / `recoverPlayback()` into `replayRegistryElements()`, whose `play()` call also catches and marks blocked (`frontend/src/app/services/remote-audio.service.ts:281-299`, `frontend/src/app/services/remote-audio.service.ts:530-552`). The banner is driven by `remoteAudioBlocked` (`frontend/src/app/services/remote-audio.service.ts:576-583`, `frontend/src/app/pages/room/room.page.html:227-232`).

4. **OK with the probe-1 caveat.** Empty output-device lists fall back to `''` through `preferredDeviceId()` (`frontend/src/app/pages/room/room.page.ts:2333-2350`, `frontend/src/app/pages/room/room.page.ts:3886-3894`). Stale non-empty output ids are intentionally retained and re-applied on `devicechange`, surfacing fallback/failure when `setSinkId` exists (`frontend/src/app/pages/room/room.page.ts:2619-2627`). Devicechange storms can overlap, but that is the excluded structural/concurrency lens. Duplicate ids collapse to the same string choice; no crash path found.

5. **BUG - already-ended audio tracks can create stuck registry elements.** `currentAudioTrack()` falls back to `tracks[0]` when all audio tracks are ended (`frontend/src/app/services/remote-audio.service.ts:594-597`), and `addPublisher()` only checks for a missing track, not `track.readyState === 'ended'` (`frontend/src/app/services/remote-audio.service.ts:428-437`). Because the `ended` listener is attached after the track is already ended (`frontend/src/app/services/remote-audio.service.ts:440-453`), it will not fire; `syncPeers()` then sees the same ended stream/track and keeps the registry entry (`frontend/src/app/services/remote-audio.service.ts:260-278`). Result: hidden audio element remains, blocked state/banner can stick, and there is no audible recovery for that publisher. A stream with zero audio tracks is OK because it is filtered out before `addPublisher()`.

6. **OK for old rows missing new fields; weak for type-corrupt rows.** Missing `remoteAudioPlayout`, `perPublisher`, `effectiveSinkId`, and `usedFallback` do not throw because the diagnostics helpers use `?? null` and `playout?.perPublisher ?? []` (`frontend/src/app/pages/diagnostics/diagnostics.page.ts:105-139`, `frontend/src/app/pages/diagnostics/diagnostics.page.ts:527-536`). Missing `mediaPlayout` also returns no row (`frontend/src/app/pages/diagnostics/diagnostics.page.ts:142-148`). I did not count string-typed/corrupt historic JSON as a new bug for this packet, but several formatters still assume non-null values are numbers (`frontend/src/app/pages/diagnostics/diagnostics.page.ts:554-575`).

7. **No additional CR5-only bug found.** I did not re-raise the prior structural/concurrency items.
