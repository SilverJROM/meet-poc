# gpt54 CODE red-team CR5 (lens L5: adversarial inputs / browser quirks / error paths)

## Findings by probe

1. `setSinkId`-unsupported browsers: bug. On browsers with no `HTMLMediaElement.setSinkId`, the sink path reports fake success instead of "default / unsupported". `applyMediaElementSinkWithDefaultFallback()` returns `'selected'` on the `!withSink.setSinkId` branch, then `RemoteAudioService.applyOutputDevice()` records `effectiveSinkId = selected device id` and `usedFallback = false` even though playout can only use the browser default output [frontend/src/app/services/remote-audio.service.ts:133-156](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:133) [frontend/src/app/services/remote-audio.service.ts:288-293](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:288) [frontend/src/app/services/remote-audio.service.ts:517-523](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:517) [frontend/src/app/services/remote-audio.service.ts:378-400](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:378). Result: no crash, but dishonest diagnostics and a false "selected speaker still active" state under iOS Safari / Firefox.

2. Garbage / negative RTCStats: bug. Non-finite stats are dropped, but negative finite counters are accepted as usable samples. `remoteVoiceSample()` only checks `Number.isFinite`, not monotonic/non-negative validity, and `decideVoiceRecovery()` / `sampleWindowHasVoiceEnergy()` then treat those samples as legitimate evidence for recovery or stall decisions [frontend/src/app/pages/room/room.page.ts:3915-3930](../../../../../../../../../frontend/src/app/pages/room/room.page.ts:3915) [frontend/src/app/services/remote-audio.service.ts:71-120](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:71). A garbage window like negative `bytesReceived` plus flat/negative `jitterBufferEmittedCount` plus rising bogus energy can falsely trigger resume/kickstart/replay/rebuild and latch the banner with no real media fault.

3. Autoplay variants: bug. Every `play()` rejection is collapsed into the same blocked state, regardless of whether it is `NotAllowedError` (gesture/autoplay), `AbortError` (transient interruption), or `NotSupportedError` (non-playable stream/codec). Both `addPublisher()` and replay treat all errors as `entry.blocked = true`, and the UI always renders "Tap to enable audio" [frontend/src/app/services/remote-audio.service.ts:479-494](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:479) [frontend/src/app/services/remote-audio.service.ts:542-550](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:542) [frontend/src/app/pages/room/room.page.html:227-231](../../../../../../../../../frontend/src/app/pages/room/room.page.html:227). That is honest for `NotAllowedError`; it is misleading for `NotSupportedError`, and it also means recovery keeps replaying a permanently unplayable source instead of surfacing a real error path.

4. Weird device enumeration: bug. Output-device selection is never reconciled when the selected speaker disappears from `enumerateDevices()`. `refreshDevices()` only repicks audio output when `selectedAudioOutputId()` is blank, unlike the input-device paths that validate membership in the current device list [frontend/src/app/pages/room/room.page.ts:2333-2350](../../../../../../../../../frontend/src/app/pages/room/room.page.ts:2333). So a stale stored output id survives indefinitely, and every `devicechange` in-call re-applies that dead id and re-triggers fallback/error handling [frontend/src/app/pages/room/room.page.ts:2619-2627](../../../../../../../../../frontend/src/app/pages/room/room.page.ts:2619).

5. Degenerate streams: bug. A stream with zero audio tracks is skipped cleanly, but an already-ended audio track is still accepted. `currentAudioTrack()` falls back to `tracks[0]` even when every track is ended, `syncPeers()` only checks truthiness, and `addPublisher()` then creates/keeps a registry element for that dead track [frontend/src/app/services/remote-audio.service.ts:255-278](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:255) [frontend/src/app/services/remote-audio.service.ts:428-495](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:428) [frontend/src/app/services/remote-audio.service.ts:594-596](../../../../../../../../../frontend/src/app/services/remote-audio.service.ts:594). If `play()` rejects, the app surfaces the generic unblock banner for a stream that cannot recover by gesture; if it resolves, diagnostics still claim a live publisher row for an already-ended source.

6. Diagnostics payload robustness: OK. The diagnostics page guards missing `remoteAudioPlayout`, `effectiveSinkId`, `usedFallback`, and `perPublisher` fields with nullish fallbacks, so old rows missing the new payload shape should render without throwing [frontend/src/app/pages/diagnostics/diagnostics.page.ts:105-149](../../../../../../../../../frontend/src/app/pages/diagnostics/diagnostics.page.ts:105).

7. Prior lenses + coordinator misses: no extra CR1-CR4-class issue proven beyond the L5 bugs above.
