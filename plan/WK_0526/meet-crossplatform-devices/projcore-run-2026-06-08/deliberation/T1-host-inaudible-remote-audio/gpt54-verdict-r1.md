## Contributing bugs / races / alternative causes (each with file:line)
- `unlockAndPlayRemoteSinks()` explicitly documents that a non-gesture caller leaves the context non-running, and the room calls it from `setTimeout(0)` after every `syncPeers()` change; that recovery path is therefore inherently incapable of fixing autoplay suspension by itself. Evidence: [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:266), [room.page.ts](/home/agjrom/websites/meet-poc/frontend/src/app/pages/room/room.page.ts:637).
- `addSource()` immediately falls into `recoverPlayback()`, which does `resumeContext()` and `output.play()` from an async non-gesture path. If the context is suspended at source-arrival time, this path can only log-and-stay-silent. Evidence: [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:464), [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:328).
- `processOntrack()` only `addTrack(event.track)` to a per-publisher `MediaStream`; it never removes/replaces older tracks. `syncPeers()` then consumes just `currentAudioTrack(stream)`, i.e. the first non-ended track. That is fragile under receiver-track reuse / replacement and can strand stale tracks in the peer stream. Evidence: [sfu-client.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/sfu-client.service.ts:804), [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:243), [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:660).
- `clearPublisherSubscriptionStateForRetry()` deletes the publisher’s remote stream outright. If a false-positive retry/reset fires, that publisher disappears from `peers()` and the mixer removes its source. Evidence: [sfu-client.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/sfu-client.service.ts:1016), [room.page.ts](/home/agjrom/websites/meet-poc/frontend/src/app/pages/room/room.page.ts:327), [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:249).
- Diagnostics cannot prove decode-vs-sink today because inbound capture only stores `audioLevel` off `inbound-rtp`; the model has no inbound `totalAudioEnergy`, and the page only renders `audioLevel`. Evidence: [sfu-client.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/sfu-client.service.ts:728), [meeting-sessions.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/meeting-sessions.service.ts:280), [diagnostics.page.ts](/home/agjrom/websites/meet-poc/frontend/src/app/pages/diagnostics/diagnostics.page.ts:46).
- Alternative cause not ruled out: sink routing to a bad-but-accepted output device. The code applies `sinkId` to the single mixer output and all media elements; only rejected `setSinkId()` falls back. Evidence: [room.page.ts](/home/agjrom/websites/meet-poc/frontend/src/app/pages/room/room.page.ts:2648), [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:652).

## Fix approach (mechanism-level, file:line — what to change and why it closes the goal)
- Fix B first in `sfu-client.service.ts`: in the no-renegotiation branch, never overwrite an existing `midToEntry` owned by a different publisher/track. At [1748-1754](/home/agjrom/websites/meet-poc/frontend/src/app/services/sfu-client.service.ts:1748), detect `rt.mid` already bound to another entry and treat that as a hard subscribe inconsistency: throw, clear the touched subscribe state, and force a retry / renegotiation path instead of rebinding. This directly addresses publisher displacement.
- Harden mid ownership globally: after `processOntrack()` / before `collectDiagnostics()`, assert 1:1 ownership between `mid` and `{publisherClientId, trackName}`. The stats builder at [728-752](/home/agjrom/websites/meet-poc/frontend/src/app/services/sfu-client.service.ts:728) should never silently attribute an existing inbound `mid` to a new publisher without an explicit teardown of the prior owner.
- Fix A in `remote-audio.service.ts` and `room.page.ts` by treating `AudioContext.state !== 'running'` as a hard playout failure, not something async recovery can solve. The code already knows this in comments and banner logic; now make the runtime behavior match it:
  keep the unblock banner latched until `contextState === 'running'` and `outputPlaying === true`,
  avoid assuming the `setTimeout` re-unlock at [637-639](/home/agjrom/websites/meet-poc/frontend/src/app/pages/room/room.page.ts:637) can resume anything,
  and add an explicit non-mixer fallback for remote playout when the mixer is blocked, instead of routing all remote audio exclusively through the mixer at [229-230](/home/agjrom/websites/meet-poc/frontend/src/app/pages/room/room.page.html:229).
- Clean up per-publisher stream lifecycle: in `processOntrack()` stop treating publisher streams as append-only bags of audio tracks. Replace/retire prior audio tracks for that publisher, or store per-track streams and let `syncPeers()` mix all live audio tracks explicitly instead of only `currentAudioTrack(stream)`. Evidence entry points: [sfu-client.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/sfu-client.service.ts:804), [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:243), [remote-audio.service.ts](/home/agjrom/websites/meet-poc/frontend/src/app/services/remote-audio.service.ts:660).
