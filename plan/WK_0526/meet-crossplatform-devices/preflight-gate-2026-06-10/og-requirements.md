# og-requirements — Pre-join Device Gate ("green room") — CONTRACT (2026-06-10)
Acceptance = every row VERIFIED (observably closed), not just green tests.

| R# | Requirement | Verify |
|----|-------------|--------|
| R1 | Before ENTERING a call, every user (host + joiners) passes a device gate. Mic + speaker MANDATORY; camera OPTIONAL (validated/preview only if access granted). | a user with no mic / blocked mic / dead mic CANNOT enter |
| R2 | Gate validates ACTUAL FUNCTION not just permission: mic captures real audio energy (live meter); speaker can play a test tone; camera shows frames (if on). | dead/muted mic blocks even though permission granted |
| R3 | Gate confirms the MEDIA CONNECTION works: the user's publish actually reaches the SFU ('published') before they are shown as fully in-call. If it cannot connect after retries → held with friendly retry, NEVER silently in-call-but-unpublished. | recreate Joanne 4b14bc30 (hasPc=false, never published): gate must HOLD + show failure, not silent-enter |
| R4 | On ANY detected issue, show an interactive device-config/test panel (Meet/Zoom-style): mic level meter, speaker test button, camera preview, device-switch dropdowns; user tests + CONFIRMS working; re-validate; only then proceed. (JROM 2026-06-10) | issue → config panel appears → switch device → test → confirm → unblock |
| R5 | HARD gate: cannot join until mic+speaker validated + connection confirmed. Friendly plain-language messages (e.g. "We can't hear your mic — check it isn't muted" / "We couldn't connect your audio"), NO WebRTC jargon. | every failure path has friendly copy + actionable next step |
| R6 | UX quality = Google Meet / Zoom green room: smooth, calm, minimal, reassuring, mobile-friendly. Not a technical gauntlet. | visual + flow review |
| R7 | Underlying fix: join->publish path is robust — publish ALWAYS fires after admit, retries, and surfaces failure loudly (no silent hasPc=false / never-publish). | code: no path where admitted client sits with hasPc=false and no error |

| R8 | Device-selection PERSISTENCE: when a user selects/changes mic / speaker / camera (in the gate, the config panel, or in-call settings), the choice is saved and re-applied on rejoin, page reload, and the NEXT call. KNOWN BUG to fix+test: selected MIC is not persisting. | pick a non-default mic -> reload/rejoin -> same mic is selected + actually in use; same for speaker + camera; covered by an automated test |

| R9 | ERROR-VISIBILITY POLICY (JROM 2026-06-10): ALL failures logged to DIAGNOSTICS always. The HOST sees a per-participant AUDIO-HEALTH indicator (e.g. a 'no audio'/'not connected' badge on a guest's tile) so the host is aware during testing. GUESTS see NO technical error text in-call for connection/publish/server failures (handled quietly: silent retry/recover). Guests' OWN green-room mic/speaker/camera SETUP HELP (test-your-device) stays guest-visible (they need it to fix their own device). Never silently un-handled — but quiet for guests. | guest connection-fail -> host badge + diagnostics, NO guest error popup; guest dead-mic -> guest green-room setup help |
| R10 | FAILURE-SIMULATION TEST MATRIX: for EACH failure mode — audio-not-reaching-server / publish-fails / hasPc=false / ICE-fails / mic-dies-mid-call / speaker-dead / device-unplugged / permission-revoked / state-revert / empty-transceiver — a test SIMULATES the failure and asserts the app DETECTS + handles correctly (recover or graceful-fail) + surfaces to diagnostics/host, and NEVER silently mishandles. Red team attacks each path. | each row of the matrix has a passing test proving handled-not-silent |
