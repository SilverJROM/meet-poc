# Phone background upload "limit exceeded" on a 1MB image (admin)

**Symptom:** silverjrom (admin, should be unlimited) got a limit error uploading a ~1MB photo from a phone.

**Two compounding root causes:**
1. **Middleware order:** the global `express.json({ limit: '1mb' })` in `createApp` runs before the backgrounds router, so it parsed/rejected the body before the route's own 30mb parser — any upload >1mb → 413 PayloadTooLargeError, which the component mislabeled as "quota exceeded." Fix: path-scoped `app.use('/api/account/backgrounds', express.json({limit:'30mb'}))` BEFORE the global parser (the global then skips via `req._body`). Removed the now-redundant inline route parser.
2. **iOS webp:** `canvas.toDataURL('image/webp')` is unsupported on iOS Safari → my resize util fell back to PNG. A 720p PNG of a photo is 1.5–3MB even from a 1MB original → tripped cause #1. Fix: resize output is now **JPEG** (universally encodable, small).

**Also:** corrected the component's 413 handling to surface the server's actual error text (so a real quota hit reads correctly, a body-size 413 reads as "too large"). Guest (non-registered) picker per-file cap 10MB → 20MB per JROM ("go back to 20MB limit for non-registered users").

**Verified:** ~2MB data-URL upload as admin → 200 (was 413). JROM's 8 real backgrounds left intact; test row cleaned.

**Generalization candidate:** a global small `express.json` limit silently shadows any route-level larger limit. Any future large-body endpoint needs a path-scoped parser registered before the global one (or raise the global).
