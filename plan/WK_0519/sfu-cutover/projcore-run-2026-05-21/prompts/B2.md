## Task (SR-2) — build the SFU client publish path (publish-only this batch)
Create a NEW frontend service (e.g. `frontend/src/app/services/sfu-client.service.ts`) — do NOT modify or replace the mesh `webrtc.service.ts` (mesh stays the live default until B8). The SFU client:
1. **One RTCPeerConnection to Cloudflare**, configured with ICE = **Cloudflare STUN (`stun.cloudflare.com:3478`) first + the existing TURN creds as fallback** (get TURN from ice-config.service).
2. **Add local tracks:** local audio sender + a **pre-negotiated video transceiver** — if the camera is OFF at join, `addTransceiver('video', {direction:'sendrecv'})` so video is negotiated up front (carry the F2/DR-55 lesson); if camera is on, add the track. Store the sender for later replaceTrack.
3. **Publish flow (through the operation queue):** createOffer → setLocalDescription → `POST /api/sfu/session` (get cfSessionId) → `POST /api/sfu/tracks` with `location:"local"` + the transceiver mids + **trackNames** → `setRemoteDescription(answer)`. Track names use the scheme `{participantId}:{sessionEpoch}:{kind}:{uuid}`.
4. **The operation queue (LOAD-BEARING, establish here):** a single serialized async queue/lock through which ALL PC-mutating operations run (publish now; subscribe/close/update/renegotiate in later batches will reuse it). No two PC mutations run concurrently. Expose an `enqueue(op)` the later batches will use.
5. **Persist the track/mid model:** keep `{trackName, kind, mid, status}` for local tracks (later batches need mids for close/update).
6. **Reachability for testing without breaking mesh:** wire the SFU client behind a BUILD/TEST flag (e.g. a `?sfu=1` query param or an injected config) so an e2e can exercise publish while the mesh remains the default join path. (The flag is temporary — it's removed in B8 when SFU becomes the only path.) Do NOT rip out or bypass the mesh join.

This batch is **publish-only** — NO remote subscribe/render yet (that's B4). Acceptance = a single client publishes audio+video to CF.
