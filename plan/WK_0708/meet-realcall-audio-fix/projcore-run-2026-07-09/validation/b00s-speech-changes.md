# B00S-SPEECH — changes.md

**Commit:** `ad702ac` fix(B00S-SPEECH): replace bot-speech tone fixtures with real piper speech + whisper gate
**Branch:** batch-01-diagnosis-2026-07-08

## Problem

`e2e/fixtures/bot-speech/{bot-140,bot-123}/*.wav` were synthetic sine tones (440Hz /
660Hz) per README + `generate-synthetic-wavs.ts`, not speech. Any transcript/hearability
arbiter running over these fixtures gets 0 words forever — false-fails or, if wrongly
relaxed, false-greens every downstream AC that claims "far end verifiably transcribes."
Documented as Defect 1 in
`decisions/2026-07-09-north-structural-speech-device-plan.md`.

## Root cause

Bot-speech fixtures were generated by a tone synthesizer as a placeholder pending piper
availability; piper was never actually run against them. Real speech existed elsewhere
in the repo (`e2e/fixtures/audio/speech/{alice-host,bob-local}.wav`, used by B08A-3)
but was never wired into the bot-speech contract ConversationScript/ConversationScheduler
consume.

## Fix

1. **Generation (SSH-only, .123):** confirmed piper already installed at
   `/home/silverjrom/voicesim/piper/piper` with `en_US-amy-medium.onnx` (22050Hz).
   Downloaded a second voice, `en_US-ryan-medium`, from
   `huggingface.co/rhasspy/piper-voices` directly onto `.123` (verified URLs resolve
   before downloading). Generated all 6 manifest utterances with piper, downsampled
   22050Hz→16kHz mono PCM via `ffmpeg` (present on `.123`; no `sox`), scp'd the 6 WAVs
   back into the repo, overwriting the tone files. Nothing installed on `.140` (this
   host) — no piper binary, model, or voice ever touched this repo/host beyond the
   generated WAVs. Voice assignment: bot-140 → amy, bot-123 → ryan (two distinct
   voices per binding).

2. **Manifests:** `bot-140/manifest.json`, `bot-123/manifest.json` — dropped the
   placeholder `rmsEstimate: 0.3` (unused by the gate, was a synthetic-tone artifact),
   added `"voice"` id per entry. `durationMs` also dropped (was an estimate tied to the
   old tone durations; not used by the gate, and re-measuring true piper durations
   wasn't in scope — flagged, not silently kept-stale).

3. **Fixture registry:** new `e2e/fixtures/bot-speech/fixtures-registry.json` — flat
   list of 8 fixtures in two classes: `scripted` (6 bot-speech entries, exact intended
   text + voice) and `already-valid` (alice-host.wav, bob-local.wav — real recorded
   speech, no fixed script, so gate only checks non-empty STT). `-long` variants and
   `.mp3` copies deliberately not registered (JROM decision: one representative WAV per
   speaker is enough).

4. **Gate test:** `e2e/harness/__tests__/bot-speech-whisper-roundtrip.test.ts` — plain
   vitest (no browser). Reuses the `runLocalWhisper` pattern from
   `b08a3-live-sender-liveness.browser.test.ts` (backend/.venv-transcribe +
   transcribe.py --force, `.participant.json` sidecar landmine handled — transcribe.py
   silently no-ops without it). For each registry entry: asserts `wordCount > 0`; for
   `scripted` entries additionally asserts the normalized transcript contains every
   key word of the intended text (stopword-light fuzzy match, not exact string — ASR
   isn't verbatim). Includes a **negative control**: runs the identical pipeline over
   `e2e/fixtures/audio/tone-440.wav` and asserts `wordCount === 0`, proving the gate
   isn't tautological (a gate that "passes" everything including tones would be worse
   than no gate).

5. **README:** rewritten — states tones are forbidden for hearability/transcript use,
   documents the real `.123`-only piper regeneration command (replacing the old
   placeholder `brew install piper-tts` / `en-us-lessac-medium` snippet that was never
   actually runnable), documents the two-voice assignment and the registry.

6. **Tone generator quarantine:** grepped the full repo for `generate-synthetic-wavs`
   references — zero real code callers (only doc mentions in prior validation/decision
   files). Moved `generate-synthetic-wavs.ts` → `e2e/fixtures/audio/_tools/` (out of
   the bot-speech path entirely) with a TONES-ONLY banner comment; fixed its internal
   `fixtureRoot` resolution (was `__dirname`, now explicitly points back at
   `bot-speech/` via `path.resolve`) so an accidental invocation from its new location
   doesn't silently create wrong-location output — kept only as a reference tone
   generator for future Mode-A stimulus needs, not wired into any test or scheduler.

## Evidence

- Gate test run (isolated): `npx vitest run harness/__tests__/bot-speech-whisper-roundtrip.test.ts`
  → **10/10 passed**, 29.98s. All 6 scripted fixtures + 2 already-valid fixtures
  whisper-round-tripped to non-empty, key-word-matching STT; tone negative control
  correctly returned 0 words.
- Full harness regression: `npx vitest run harness/__tests__ --exclude "**/*.browser.test.ts"`
  → **122 passed, 5 skipped**, 10/10 test files, no failures. (A separate,
  pre-existing `--exclude` scoping issue causes vitest to also try collecting
  unrelated Playwright `.spec.ts` files under `tests/v3-*` when run without a path
  filter — reproduced identically on HEAD before this commit's changes were staged,
  unrelated to this batch, not touched.)
- No leftover scratch sidecars (`.participant.json`, `.transcript.*.json`) after test
  runs — confirmed via `git status` immediately post-run, all cleaned by the test's
  `afterEach`.
- `git mv` used for the quarantine (rename tracked, not delete+add).
